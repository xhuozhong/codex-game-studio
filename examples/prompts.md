# 示例调用

在实际游戏项目内使用；先准备该项目所需的运行环境与浏览器工具。

## 接管已有项目

```text
$game-studio-director

读取项目说明、现有代码、进度和测试配置，确认引擎与真实运行命令。
完成下一项最重要的玩家可见功能，一个主负责人、最多三个辅助专家。
保留已有存档和可用功能，不添加多人、账号或付费服务。
实际运行并试玩，检查截图、状态、Console，修复后回归。
报告真实结果与未解决问题，更新进度文档。
```

## 从零做一个像素经营小游戏

```text
$game-studio-director

做一个浏览器像素经营小游戏，第一阶段只有一个可玩的最小循环：
八方向移动、一个 NPC、播种浇水成长收获、昼夜、背包、保存读取。
支持键盘与手机触控。不要大地图、多人、账号和大量剧情。
先验证 NPC → 耕种 → 收获 → 保存 → 刷新恢复的完整旅程。
```

## 提升操作手感

```text
$game-feel

检查当前移动、攻击、拾取和按钮反馈。
改善响应、动画节奏、适量粒子和音效；尊重减少动态效果设置。
不改经济、奖励或碰撞规则。用实际输入检查效果。
```

## 手机 UI 与交互

```text
$game-ui-ux

检查当前 HUD、背包、菜单与触控按钮。
覆盖桌面、手机横竖屏，检查安全区域、焦点和触控遮挡。
运行并检查截图，不只调整 CSS 数值。
```

## Three.js UI

```text
$threejs-game-ui-designer

为当前 Three.js 游戏完善 HUD、暂停菜单与触控 Overlay。
说明哪些 UI 放进 DOM，哪些需要在 3D 场景内。
验证缩放、转屏、菜单交互与场景切换。
```

## 明确启用多人联机

```text
$game-studio-director

这次允许启用 multiplayer-game，把当前稳定单人原型扩展成两人合作。
先定义服务器权威状态、房间生命周期、消息格式与重连边界。
用两个真实客户端测试加入、同步、同时操作、掉线重连和房间清理。
不添加支付或商业账号系统。外部服务费用另行确认。
```

## 回归已有游戏

```text
$develop-web-game

完整走通新游戏 → 移动 → NPC互动 → 收获 → 背包 → 保存退出 → 刷新读取。
检查关键截图、状态、Console 和资源失败。
发现问题后修复并重跑。不可运行的项目单独标明阻断原因。
```

## 部署准备

```text
$game-studio-director

为当前已验证的游戏准备公开部署，沿用现有托管方案。
核对资源路径、构建输出、存档、版权、隐私和回滚方案。
先完成可审查的发布产物；只有已有明确授权才执行外部部署。
发布后验证线上关键旅程，不把本地运行等同于部署成功。
```
